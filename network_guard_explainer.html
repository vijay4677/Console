Network Guard Flow

How the guard works

The `.pth` file loads `network_guard.bootstrap` at Python startup. Bootstrap installs the interceptor. The interceptor only blocks requests to `localhost:8080`, so SDK traffic can go through while direct test traffic to the protected port gets rejected.

Mindmap

Startup path, allowed SDK path, and blocked direct path.

Step-by-step

  • Python starts inside the venv or Dataiku code env.
  • The `.pth` file imports `network_guard.bootstrap` automatically.
  • Bootstrap installs the interceptor once.
  • Requests to `localhost:8080` are the only ones blocked.
  • Direct `requests`, `httpx`, `urllib`, or raw socket calls to that port raise `DirectNetworkBlockedError`.

Example flow

import mylib1 import requests print("Before SDK") print(mylib1.send_greet("Vijay")) response = requests.post( "http://localhost:8080/greet", json={"name": "Hello"}, )

`mylib1.send_greet()` is allowed. The direct request to `localhost:8080` is blocked.

What this does not block

  • Other hosts and ports.
  • Requests outside this Python interpreter.
  • `curl` or another app unless it hits the same blocked endpoint from the same process path.
